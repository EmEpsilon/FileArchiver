# FileArchiver テストケース設計

本書は、各テストが **単機能テスト** か **実運用想定シナリオテスト** かを明示し、
狙い・前提・検証観点を整理したものです。

## 1. テスト分類

- **単機能テスト**: 1つの機能仕様を狙い撃ちで検証する
- **実運用想定シナリオテスト**: 実際のバッチ運用で起こる流れ（設定→実行→副作用）をまとめて検証する

## 2. 現在の自動テスト一覧

| ID | テスト名 | 分類 | 想定状況 | 主要入力 | 主な期待結果 |
|---|---|---|---|---|---|
| TC-001 | 初期設定: --init-config でテンプレートファイルを作成する | 単機能 | 初期導入 | `--init-config custom.toml` | テンプレート作成 |
| TC-002 | Dry-run: 圧縮対象でもファイルは圧縮されない | 単機能 | 本番前の影響確認 | `--dry-run` + 圧縮条件成立ファイル | ZIP未生成・元ファイル残存 |
| TC-003 | 通常実行: 期限超過ファイルを圧縮し元ファイルを削除する | 実運用想定 | 日次実行 | 圧縮条件成立ログファイル | ZIP生成・元ファイル削除 |
| TC-004 | 非Windows: EnableEventLog=true でフォールバックログファイルへ出力する | 単機能 | Linux/macOS運用 | `EnableEventLog=true` | フォールバックログ作成 |
| TC-005 | リネーム: EnableRename=true で期限超過ファイルをリネームする | 単機能 | ローテーション運用 | `EnableRename=true` | 末尾タイムスタンプ付きリネーム |

## 3. 実運用想定シナリオの補足

### 3.1 日次アーカイブ運用（TC-003）

- 想定: 毎日夜間に古い `.log` を圧縮
- 検証軸:
  - 圧縮ファイルが生成される
  - 元ファイルが削除される
  - ZIP 内エントリ名が正しい

### 3.2 本番前リハーサル（TC-010）

- 想定: 設定を複数機能ONで投入する前に Dry-run 実施
- 検証軸:
  - rename/delete/compress の副作用が一切発生しない

## 4. 単機能テストの補足

単機能テストは不具合切り分けを容易にするため、
1ケース1責務で「設定値と結果の対応」を明確にしています。

## 5. 今後追加すべきテスト（優先順）

1. **実運用想定**: `SummaryOutputPath` の JSON 件数整合性（ログ件数と照合）
2. **単機能**: 終了コード `0/2/3` の明示検証
3. **実運用想定**: 大量ファイル（数万件）での性能回帰テスト

## 6. テスト実行方法

```bash
dotnet test FileArchiver.sln -v minimal
```

Visual Studio では Test Explorer から `ArchiverBehaviorTests` を実行可能です。
